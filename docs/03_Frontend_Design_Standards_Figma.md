## 1. 最高优先级规则
1. 后续前端设计与实现必须优先遵循本文件。  
2. 若本文件与历史页面冲突：
- 新页面按本文件执行。
- 老页面逐步改造到本文件标准。
3. 若本文件与 Figma 原稿冲突，以 Figma 原稿为准，并更新本文件。

## 2. 视觉基础（Design Tokens）

### 2.1 颜色（已提取）
- `--brand-primary`: `#0064FF`
- `--brand-cyan`: `#33DDFF`
- `--text-primary`: `#16171A`
- `--text-secondary`: `#696A6D`
- `--bg-base`: `#FFFFFF`

### 2.2 背景风格
- 使用浅色基底 + 大面积柔和模糊渐变块（品牌蓝/青）。
- 视觉基调：克制、清晰、企业化，不使用高饱和杂色背景。

### 2.3 字体与层级
- 主字体：`Plus Jakarta Sans`（英文/数字）。
- 中文补充：`Noto Sans`（或项目内中文等价字体）。
- 已识别标题参考：28/42（weight 700），正文参考：28/42（weight 400），说明文参考 24/36。

## 3. Logo 使用标准（强制）

### 3.1 结构原则
- 产品 logo 由两部分组成：
1. Graphical image
2. Product name
- 两部分必须按官方组合关系使用，不得随意拆分重组（除图标特定场景）。

### 3.2 ONES 主品牌与子品牌/产品并列
- ONES logo 与产品 logo 并排时必须使用分隔符 `|`。
- 分隔符与两侧 logo 保持规范间距（Figma 标注为 `1/2a` 级别）。
- 分隔符高度与比例需保持规范（Figma 标注为 `b`）。
- ONES 文本与产品品牌文字需视觉居中对齐。

### 3.3 禁止项（来自规范页）
- 禁止倾斜、旋转、镜像 logo。
- 禁止改变 logo 颜色。
- 禁止添加描边、阴影等特效。
- 禁止拉伸/压缩导致非等比变形。
- 禁止修改 logo 元素比例和字形。
- 禁止将 logo 放在复杂、干扰性强的背景上。
- 禁止在不清晰或低辨识场景中使用模糊 logo。

## 4. 页面构图标准
- 顶部统一品牌头：左侧 ONES logo + `|` + 页面分区标题（如 `Global Blog` / `ONES logo` / `Product logos`）。
- 主内容区遵循「左文案右示意」或「上示意下说明」布局。
- 文案强调层级：
1. 大标题（强识别）
2. 规则正文（说明）
3. 次级说明（灰阶）

## 5. 对产品前端的落地要求
1. Portal、Agent Console、帮助/品牌说明页统一使用以上 token。  
2. 所有 logo 相关组件抽象为统一组件，不允许页面内手写 logo 拼接。  
3. 新增页面必须通过“品牌一致性检查”（见第 6 节）。

## 6. 交付前检查清单（每个前端 PR 必做）
- 是否使用标准色值（brand/text）？
- 是否沿用标准字体与字重层级？
- 是否存在 logo 误用（变形/改色/特效/错位）？
- 是否符合浅色+柔和渐变背景风格？
- 是否保持页头品牌结构一致？
- 是否在 PR 描述中声明“已按 `03_Frontend_Design_Standards_Figma.md` 自检”？

## 7. 后续维护
- 新增 Figma 规范页时，必须同步更新本文件。
- 建议在代码库增加 `design-tokens.css` 与 `BrandLogoUsage` 组件，确保规则可执行。
