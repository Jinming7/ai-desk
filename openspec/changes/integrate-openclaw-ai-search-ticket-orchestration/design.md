## Context

当前系统的 AI 搜索与工单流程是分离的：搜索返回缺少知识来源引用，失败场景下需要人工跳转并重复录入。目标是将 OpenClaw 接入现有检索层，并通过 Agent 编排将失败请求自动升级为“深层检索 -> AI 解决或正式建单”的闭环。约束包括：
- 需要兼容现有搜索接口与前端交互，不破坏已有调用方。
- 引用文档需要可追溯（文档 ID、标题、片段、来源链接、检索时间）。
- Ticket 创建需携带完整上下文并满足工单系统字段校验。
- Agent 执行必须具备幂等与超时控制，避免重复建单。

## Goals / Non-Goals

**Goals:**
- 让 AI 搜索在可回答时返回“答案 + 参考文档”。
- 让 AI 搜索在不可回答时暴露快速提 ticket 按钮，并把会话上下文透传到升级流程。
- 让 Agent 在提单后做深层知识库检索，依据结果自动分流：可解则 AI 解决，不可解则创建正式工单。
- 建立全链路可观测数据（检索质量、升级率、自动解决率、建单率、失败原因）。

**Non-Goals:**
- 不改造 OpenClaw 底层索引构建与内容治理策略。
- 不重构现有 Ticket 平台领域模型，仅做必要字段映射与流程编排。
- 不在本次变更中实现复杂的人审工作流（如多级审批）。

## Decisions

1. 统一采用“检索编排网关”封装 OpenClaw 与 LLM 调用。
- 决策：新增 `SearchOrchestrator` 层，负责 query 预处理、OpenClaw 检索、引用组装、答案置信度判定。
- 原因：避免前端或业务服务直接耦合 OpenClaw 协议，便于后续替换或多检索源扩展。
- 备选：在 AI 搜索服务内直接调用 OpenClaw。未选原因是耦合高、扩展差。

2. 失败升级采用显式状态机（SEARCHED -> ESCALATED -> DEEP_RETRIEVED -> RESOLVED|TICKET_CREATED）。
- 决策：以状态机驱动 Agent 编排，所有转换带事件日志与幂等键。
- 原因：流程可审计、可重试，且便于 SLA 统计。
- 备选：通过松散异步任务串联。未选原因是状态不可观测、失败恢复复杂。

3. “快速提 ticket”只作为升级触发入口，正式建单由 Agent 最终裁决。
- 决策：用户点击快速提 ticket 后先创建升级任务记录，不立即创建外部工单。
- 原因：满足“先深层检索再决定是否建单”的需求，减少低质量工单。
- 备选：点击即建工单。未选原因是会增加无效工单与重复处理。

4. 深层检索使用多轮策略（关键词扩展 + 语义检索 + 证据重排）。
- 决策：Agent 在单次升级中最多执行 N 轮检索，达到置信阈值则返回可执行方案，否则转建单。
- 原因：平衡解决率与时延。
- 备选：单轮检索。未选原因是复杂问题覆盖不足。

5. 前端交互采用非阻塞反馈。
- 决策：搜索失败时展示快速提 ticket 按钮；提交后展示“Agent 处理中”状态并支持结果回查。
- 原因：减少用户等待焦虑，并保持交互连贯。
- 备选：同步等待 Agent 结果。未选原因是时延不可控。

## Risks / Trade-offs

- [OpenClaw 检索质量波动] -> 通过置信度阈值、重排策略和质量监控（命中率/引用覆盖率）持续校准。
- [Agent 深层检索导致响应变慢] -> 采用异步编排、轮次上限、超时降级与用户可见进度提示。
- [重复升级或重复建单] -> 使用幂等键（query/session/user）和外部工单去重索引。
- [自动解决建议不准确] -> 增加最小证据要求（至少 2 条相关引用）与低置信度禁自动解决策略。
- [接口变更影响现有调用方] -> 采用向后兼容字段扩展，不移除现有响应结构。

## Migration Plan

1. 增加配置与依赖：接入 OpenClaw 凭证、检索索引标识、Agent 编排队列配置。
2. 灰度发布后端：先上线 `SearchOrchestrator` 与升级状态机，保持旧路径可回退。
3. 灰度发布前端：逐步开放“参考文档展示”和“快速提 ticket”按钮。
4. 开启 Agent 深层检索：按租户或流量比例放量，观察自动解决率与建单质量。
5. 完整切换并清理旧逻辑：确认指标稳定后移除旧失败处理分支。

回滚策略：
- 关闭功能开关（KB 引用、快速提 ticket、Agent 深检）回退到原始 AI 搜索流程。
- 保留升级记录但暂停外部工单创建，防止错误扩散。

## Open Questions

- OpenClaw 的检索限流与 SLA 是否满足高峰流量，需要预热或缓存策略吗？
- 自动解决的置信阈值初值应按全局统一还是按业务域分层配置？
- 工单系统最小必填字段与优先级映射规则是否已有统一规范？
- 是否需要在人机协作场景下支持“用户确认后再执行自动解决”？
